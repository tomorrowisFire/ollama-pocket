## Proposed product design — to freeze after F3B gate
A / UX: a real in-app, user-started conference distinct from the plan compiler and conventional chat. User enters a goal and chooses a local model; the screen shows separately labeled Planner, Producer, Reviewer turns, then the current artifact, unresolved issues, actual deterministic check and attempt count. Start once, no extra "next" commands; explicit stop, visible partial results, explicit copy/apply only. Show that one model plays all three roles sequentially; never imply three independent models, humans or concurrent agents. Do not equate a favorable review with factual verification.
B / engineering: start F4A as a separate, bounded in-memory text-only coordinator using an injectable generator policy and the existing local CPU Ollama streaming path. Do not overload or migrate the existing durable workflow checkpoint. Strict typed role outputs with separate plan/artifact/issues fields; feed original goal and prior role output as bounded, untrusted data. Use one explicit user-provided existing output predicate (same exact WorkflowPolicy semantics) for an artifact, independently of a reviewer's structured ACCEPT/REVISE recommendation. Initial planner/producer/reviewer calls; at most one producer/reviewer correction pair (<=5 requests, not arbitrary recursive work), finite per-call token/output and total monotonic deadline. Proposed caps: goal <=400 UTF-16 units; 2048 context estimate before every call; <=512 generated tokens/call, <=4000 UTF-16 output/call, total <=5 requests and <=5 minutes; choose tighter per-role payload bounds before implementation so ordinary CJK goals can fit. Fail safely when context cannot fit, never silently truncate user input or prior artifact. Keep role transcripts/result for current foreground session only; no new automatic storage, background service, network endpoint, cloud transfer, tool/file execution or permission.
C / QA: completion means only "configured predicate matched and model recommended acceptance" after current artifact's review. Reviewer ACCEPT alone, producer self-score, malformed/truncated output, missing role evidence, a stale review of a previous artifact, user stop or deadline never completes the run. Reviewer REVISE or failed predicate can request one bounded correction; if still unmet, BLOCKED with last valid partial artifact. Transport/safety failure stops rather than blindly retries. Goal, criteria and model frozen on start. Preserve actual role turns in order; a stopped call does not become a completed turn. Cancel disconnects the request and prohibits later completion/apply. Distinguish model limitations from independent real evidence. Preserve production ad lock, all existing model/history/engine settings and manual MCP boundaries.
