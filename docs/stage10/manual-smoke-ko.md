# OnHand AI — 실기기 인수검수 순서 (미실행)

대상: 정확한 앱 소스 커밋과 해당 APK SHA-256. 운영 광고는 잠금 상태 유지. 테스트는 전용 기기/프로필과 합성 데이터로 진행한다. 기존 앱의 서명이 다르면 설치 중단: 기존 앱을 삭제하거나 초기화하지 않는다.

## 0. 증빙 준비
- API 36, ARM64, 4KB/16KB 실제 페이지 크기 기기의 ADB 사전 점검: `python scripts/collect_device_evidence.py --out device-preflight.json`. ADB 메타데이터는 사전 확인만이며 PASS 아님.
- `apksigner verify --verbose --print-certs <APK>`로 테스트 APK 서명 확인. 기존 설치와 업데이트 서명이 맞는지 별도 확인한다.
- 최신 동일 커밋 CI·APK·QA AAB와 실제 16KB 보고서를 확보한다. 이전 빌드로 새 커밋을 승인하지 않는다.
- 입력 데이터와 스크린샷에는 실명·업무 문서·키·연결 코드가 없어야 한다.

## 1. 대표 과업

| 관점 | 실행 과업 | 통과 조건 |
|---|---|---|
| A 일상 활용 | 로컬 모델로 3턴 대화→질문 수정→재생성→중지→재실행 | 저장된 완료 턴 및 초안 보존, 중복 답변·잘못된 문맥 없음 |
| B 문서 | 합성 TXT(CP949), DOCX, XLSX, PDF 텍스트/스캔 샘플 각 1개 첨부→추출 범위 편집→요약 | 알려진 원문 값과 결과 비교, 부분/OCR/편집 여부 표시. 누락을 전체 분석으로 주장하지 않음 |
| C 코딩 | 2개 단순 계산 문제와 입력 검증 함수를 생성하도록 요청→출력 복사→격리된 테스트 환경에서 실행 | 코드 복사와 기능 테스트의 실제 결과 기록. 앱에 없는 코드 실행은 별도 환경으로 명시 |
| D 자동화 | 아래 10단계 계획 한 번 실행→중간에 일시정지 및 재개. 별도로 실패 검증기·강제 종료 후 복구 확인 | 10단계 각각 검증 통과 또는 이유 명시 차단, 완료 단계 재실행 없음, 시간/시도 제한 유지 |

| F 음성 | 지원 언어별 고정 문장 받아쓰기·연속 음성 대화·긴 답변 읽기→중단 | 초안 보존, 오인식/권한 거부 안전 처리, 녹음/재생 지연 및 실제 성공률 기록 |
| G 로컬 | 동일 모델/프롬프트 CPU→Vulkan→2~3대 RPC 비교 및 게스트 연결 해제 | 실제 tok/s·첫 출력·최소 가용 RAM·온도·모델 없는 게스트 검증, 실패 안전 처리 |
| H UI | 360/600/720/840/1024dp, 확대 126% 이상, 가로/세로·분할·키보드·태블릿 설정 | 입력창 및 핵심 버튼 접근, 화면 잘림/겹침 없음, TalkBack/포커스 순서 확인 |
| I 언어 | 한국어/영어/일본어/중국어 간·번체 순환, 오류·권한·광고 화면 포함 | 원어민 또는 별도 검수 기준, 누락·줄바꿈·숫자 및 상태 표기 확인 |
| J 개인정보 | 외부 전송 승인 취소→MCP 허용/철회→협력 종료→문서 캐시·백업·클립보드 확인 | 실제 네트워크·기기 로그를 검토하여 승인 없는 전송 없음, 암호화·세션 종료 및 데이터 보존 확인 |

## 2. 10단계 자동진행 합성 계획
아래는 실행기 순차 구조를 시험하는 합성 계획이며 업무 결과의 품질이나 실제 90점 평가를 대신하지 않는다. 모델을 준비하고 로컬 CPU 모드에서 시작한다. 협력 세션은 종료한다.

```text
Reply with STEP01 only. | @exact:STEP01
Reply with STEP02 only. | @exact:STEP02
Reply with STEP03 only. | @exact:STEP03
Reply with STEP04 only. | @exact:STEP04
Reply with STEP05 only. | @exact:STEP05
Reply with STEP06 only. | @exact:STEP06
Reply with STEP07 only. | @exact:STEP07
Reply with STEP08 only. | @exact:STEP08
Reply with STEP09 only. | @exact:STEP09
Reply with STEP10 only. | @exact:STEP10
```

별도 실패 케이스: `Reply with WRONG only. | @exact:EXPECTED`. 모델이 실제로 WRONG을 출력했을 때 검증 실패가 기록되고 최대 3회 시도 한도가 유지되는지 확인한다. 모델이 EXPECTED를 출력하면 이 케이스는 실패 주입으로 성립하지 않는다. 프로세스 종료 테스트는 전용 테스트 환경에서만 수행하며 운영 데이터 삭제 금지.

## 3. 인수 기록
각 과업에 날짜, 후보 커밋, APK 해시, 기기/페이지 크기, 실제 입력·결과, 소요 시간, 오류, 스크린샷/로그(민감정보 제거), PASS/FAIL/NOT_RUN을 기록한다. 점수는 관점별 과업 30/편의 25/신뢰 20/성능 15/안전 10으로 실측과 관찰을 반영한다. 전체 평균과 전원 90 이상, 미해결 P0/P1 0건, 모든 필수 게이트 PASS가 필요하다. 모의평가는 별도 참고 자료이며 실제 평가 증빙이 아니다.
