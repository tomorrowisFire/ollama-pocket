## Proposed A/B/C agreement (one assistant, three simulated roles)
A: independent project list, title and instructions; text artifacts with title, immutable versions and explicit restore. No auto-injection into model prompts. Show count/size limits before committing; never evict old versions to make space.
B: one fixed private no-backup file, with canonical bounded payload and digest envelope, explicit schema/revision. Use exact UTF-8 byte lengths (including serialized escaping and envelope) not character counts. File name never comes from user/model. One in-process serialized transaction; load and validate exact expected digest/revision; pure mutation; validate full candidate and cap; write via AtomicFile; handle failure and re-read/validate committed payload before reporting success. Never initialize empty over a damaged/unknown-schema file. On actual write uncertainty, report failure/uncertain status and re-read, never claim successful rollback or commit without evidence. Use deterministic explicit IDs and strict Unicode handling; no export/import/remote sync yet.
C: preserve source text exactly including whitespace, newlines, quotes and Unicode. Reject unpaired surrogates and malformed UTF-8; digest is corruption detection, not encryption. A failed limit, stale edit or corrupt read must not write anything. Device-only durability and crash behavior are deferred; Java fake backend tests do not prove Android fsync or power-loss recovery.

## Candidate data contract (to freeze after F4B2)
- Outer envelope: schema 1, canonical payload string, SHA-256 hex of exact payload UTF-8. Payload contains store revision, projects; each project contains stable ID, title, instructions, artifacts. Artifacts contain stable ID, title, ordered immutable version list. Each version has increasing ordinal, saved time and exact text. Restore appends the selected historical text at a new ordinal; no historical version replacement. Metadata edits never rewrite version text.
- Proposed ceilings: 12 projects, 20 artifacts/project, 6 versions/artifact, 32000 UTF-16 units/version, 2 MiB UTF-8 total envelope. Titles <=80 UTF-16, instructions <=2000; IDs generated by app. New content rejected at ceiling; explicit deletion only. Total cap is independent of item caps, so not every project can reach every individual maximum. No silent data loss.
- Global revision increments once per committed mutation. Stale captured revision+digest blocks mutation. Identical text can be rejected as no-op rather than creating spurious version history. Specify exact no-op behavior before implementation. Deleting project removes only its own records.

## Proposed fixture checklist
| Group | Mandatory cases |
|---|---|
| Identity/schema | Empty missing store vs corrupt existing; unknown schema; missing/wrong/extra fields; duplicate project/artifact IDs; malformed ordinals, timestamps and digest; malformed UTF-8/unpaired surrogate |
| Isolation | Two projects with identical artifact titles; wrong project/artifact lookup; edit and delete project A without changing B; original chat/workflow/settings untouched |
| Versioning | Create v1; append v2; restore v1 as v3; exact text equality of v1/v3; v2 unchanged; no-op; seventh version rejected without mutation |
| Limits | 12/13 projects; 20/21 artifacts; 6/7 versions; 32000/32001 UTF-16; 2 MiB/overflow actual envelope bytes with ASCII, Korean, Chinese, emoji, quotes, escapes |
| Transaction | Correct captured revision commits once; stale revision or digest fails before write; fake write failure; post-write read mismatch reports uncertain/failure; reload returns only validated content; never overwrite corrupt store |
| UI | Create, select, edit, save, restore, delete confirmation; empty/error state; 5 locale strings; no automatic copy or model call; secure dialog and lifecycle close |
| FINAL device | AtomicFile interruption/kill/relaunch, actual persistent versions, UI/IME/rotation/accessibility, storage cap, no backup or transfer, no chat regression |
