## Proposed F5 phased implementation
### F5A — local project repository and workspace UI
A / UX: project creation, title and instructions, project list, manually added text artifacts/notes, selected artifact detail, explicit edit/save and version viewing. Clear storage usage and bounded capacity errors. Workspaces independent of model selection; no active-project prompt injection or model invocation. Secure dialogs, five locales. Use a project entry in local chat actions; close on activity pause. Existing chat actions, sidebar and startup ad retained.
B / engineering: one versioned private store, separate from chats/settings, bounded deterministic data model and atomic transactions. Proposed caps: 12 projects; 20 artifacts/project; 6 versions/artifact, 32000 UTF-16 units/version; serialized store <=2 MiB UTF-8 (choose exact limits before freezing). Cap title/instructions/IDs, strict schema and unique IDs, exact version text preservation, digest and revision checks; no path names from user/model text. Stable IDs, per-project lookup and mutations, immutable historical versions, explicit restoration by appending a new version (never rewriting history). Reject cap overflow without deleting or overwriting existing data. Use app-private AtomicFile or equivalent atomic commit with stale-snapshot recheck; bounded reads; corrupt/unknown-schema state fails closed rather than being initialized as empty. Digest checks detect corruption, not encryption or protection against a privileged device user. No auto-save of chat/clipboard/model output; no API keys or storage of hidden application settings. Explicit deletion only with review; project deletion removes only its own data, not source conversations/files.
C / QA: deterministic Java tests for strict schema, bounds, immutable version chains, project isolation, Unicode exactness, duplicate/stale IDs/revisions, failed writes leaving prior data unchanged, corruption handling, no silent eviction. Separate source/CI checks from Android AtomicFile crash/process-death tests (FINAL). Keep actual identity of all original data and ad/signing; no inference or network from project management.
